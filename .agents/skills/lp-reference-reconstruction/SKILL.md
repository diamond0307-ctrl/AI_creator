# LP参考画像 再構築 Skill

参考画像がある状態でLPのヒーローやセクションを実装するときに使う。参考画像は「なんとなく似た雰囲気を出すためのインスピレーション」ではなく、**再現すべき完成済みの設計図**として扱う。

このSkillは [AGENTS.md](../../../AGENTS.md) のレイアウト構成方針(単純な縦積みを避け、雑誌広告・エディトリアルデザインのように要素が関係し合う構成にする)を、参考画像がある場合に具体的にどう実行するかを定めるもの。

## いつ使うか

- ユーザーが参考画像(スクリーンショット、雑誌広告、既存LPの画像など)を渡してきて、それに似せたセクションを作ってほしいと言っているとき
- 既存セクションを参考画像により忠実な構成へ作り直すとき

参考画像がない単純なセクション(通常のテキストブロックや、単体の画像+キャプション程度のもの)を作るときは、このSkillを無理に適用しない。通常のLP制作フローで問題ない。

## ワークフロー

### 1. 参考画像を設計図として分析する

参考画像を「完成した設計図」として読み解く。雰囲気だけを言語化して終わらせない。以下の要素を構造化して洗い出す。

- 見出し・キャッチコピーのテキスト内容、フォントサイズの相対関係、配置位置
- 人物写真の有無、切り抜き方、画面内での位置・スケール・視線の向き
- モックアップ(スマホ画面、UI、製品画像など)の位置・角度・重なり
- カード・バッジ・数値・アイコンなどの補助要素とその配置
- CTAの位置・形状・サイズ
- 余白の取り方、要素間の視覚的な密度
- 要素同士の重なり(どれが手前で、どれが奥か)
- 全体の視覚的ヒエラルキー(最初に目に入る順序)

### 2. HTML/CSSで作る要素と画像素材にすべき要素を判断する

要素ごとに、どちらで実装するのが適切かをその都度判断する。固定の比率や工程数を決めつけない。

- テキスト、単純な図形、単色/グラデーション背景は基本的にHTML/CSSで実装する
- 人物の切り抜き、複雑な質感を持つモックアップ、写真同士の合成など、CSSの箱では再現できない要素は画像素材として生成・加工する
- 1つのセクションに必要な画像素材の数は参考画像の複雑さに応じて変わる。前回のセクションで採用した素材数や工程をそのまま次のセクションに流用しない

### 3. 必要な画像素材を先に用意する

画像素材が必要と判断した場合は、レイアウトを組む前に素材を生成・加工しておく。素材が揃わない状態で見切り発車でレイアウトを組まない。

### 4. compositionコンテナで組む

通常の縦積み(各要素を順番にmarginで積んでいくだけの構成)では参考画像の重なりや非対称性を再現できない場合、素直に縦に並べるのではなく、以下のような手法を必要に応じて使う。

- セクション全体を1つの `position: relative` なcompositionコンテナとして扱う
- 個々の要素(人物、モックアップ、テキストブロック、カード、CTA)を `position: absolute` / `transform` で参考画像の相対位置に配置する
- 参考画像内での各要素の相対位置・スケール比・重なり順(z-index)・視覚的ヒエラルキーを保持する
- モックアップは単なる四角い画像として無造作に置かない。傾き、影、重なり、周囲の要素との干渉を含めて配置する
- 文字を人物や重要なビジュアル要素に重ねる場合、顔などの重要な部分に誤って被らないよう、位置・背景の暗さ・テキストシャドウなどで調整する

すべてのセクションを毎回absolute配置で組む必要はない。参考画像の構成上、通常のFlex/Gridで十分に再現できる部分は無理にabsolute化しない。

### 5. 実装後にスクリーンショットで比較・調整する

- 実装したら必ずブラウザでスクリーンショットを撮る
- 参考画像と並べて、位置・サイズ・重なり・タイポグラフィ(フォントサイズ・行間・太さ)のズレを確認する
- 開発中の比較がしやすいよう、必要であれば参考画像を半透明のoverlayとして重ねて位置合わせしてもよい
- ズレがあれば座標・スケール・余白を調整し、再度スクリーンショットで確認する。これを参考画像に十分近づくまで繰り返す
- 完成したら、比較用に入れたデバッグ用overlay(半透明の参考画像レイヤーなど)は必ず取り除く

## 注意

- ここで扱う「画像素材を何枚に分けるか」「どの要素を画像化するか」は毎回セクションごとに判断するものであり、固定の枚数や固定の工程として覚えない
- 参考画像の忠実な再現を優先するあまり、実データ(コピー、価格、実績など)を捏造しない。テキスト内容はユーザーから提供された情報を使う
